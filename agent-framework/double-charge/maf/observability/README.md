# Observability and durable audit

PostgreSQL is authoritative for state, approvals, outcomes and the durable business
audit. MAF owns its checkpoints. Sampled or expiring telemetry is **not** proof of
exactly-once side effects or a replacement for either store.

## Export paths and ownership

`maf_double_charge.infrastructure.telemetry.configure_telemetry(settings,
host="api")` explicitly selects one process-wide path:

| Runtime/configuration | Export path | Lifecycle owner |
| --- | --- | --- |
| API + `APPLICATIONINSIGHTS_CONNECTION_STRING` | Azure Monitor OpenTelemetry distro: traces, safe application logs, selected native metrics | API |
| API + `OTEL_EXPORTER_OTLP_ENDPOINT` | OTLP/HTTP traces, safe application logs, selected native metrics | API |
| API + neither | No provider or exporter created | None |
| `host="hosted"` | Existing platform tracer/exporter; no distro initialization or provider replacement | Hosted platform |

Selecting both API destinations is an error, not duplicate export. Hosted mode
requires the platform SDK tracer provider to exist before lazy application runtime
creation. It does not use the API connection string or OTLP destination. Never set
the platform-reserved `APPLICATIONINSIGHTS_CONNECTION_STRING` in hosted `azure.yaml`.

Configuration is explicit, not module-import work. Identical calls share one handle;
changing a live configuration requires a process restart. The API factory calls
`instrument_api_app(app, settings)` **before** middleware is built. OpenTelemetry
proxy providers let actual exporter creation remain in the runtime lifespan.
Already-configured callers may instead use `TelemetryHandle.instrument_app(app)`.
HTTP clients, SQL drivers, OpenAI content capture and unrelated frameworks are not
blanket-instrumented.

`TelemetryHandle.shutdown()` first attempts a bounded flush on every owned provider
and then shuts down all of them, even if another provider fails. It is idempotent.
Hosted/disabled shutdown is a no-op: application cleanup must not shut down the
platform exporter. Export network timeouts are five seconds. Flush and shutdown
each have a five-second **caller wait** budget, across all owned providers.
SDK 1.44's batch flush does not honor its timeout argument, so bounded daemon
workers enforce these budgets. A timed-out operation may finish later; that
provider's shutdown waits for its flush rather than racing it. Other providers
still close. This is best-effort telemetry delivery, not cancellation or a
guarantee of delivery before process exit; SDK atexit behavior remains SDK-owned.

## Native hierarchy and safe correlation

The SDK supplies workflow, edge-group, executor, agent/model and message-send spans.
Their actual parents, links, timestamps, status codes and safe native names survive
sanitization. No substitute hierarchy is fabricated. Usage counters are exported
only when the SDK/model reports them; missing token values are not zero.

Use `telemetry_context(case_id=..., run_id=..., conversation_id=..., response_id=...)`
around command execution. It enriches the current request and native child spans,
restoring context after the command. Start, approval and resume normally have
different trace IDs; join their `case_id`/`run_id` attributes instead of keeping one
span alive through an approval pause. Hosted conversation/response IDs are included
only when supplied, not invented.

Correlation values are `sha256:<hex>` join keys, generated by
`infrastructure.logging.correlation_id`. This is deterministic pseudonymization,
**not** encryption or a claim of anonymity: someone with a candidate business ID can
calculate the same hash. Raw case/run/conversation strings cannot smuggle complaint
text into telemetry. SQL audit queries continue to use the actual business IDs.

## Redaction boundary

- MAF `enable_instrumentation(enable_sensitive_data=False)` explicitly disables
  prompt, response and tool-argument/result emission; message-content events are off.
- Hosted configuration must additionally set
  `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT=false` before the Responses SDK
  initializes. Platform content capture is not controlled by MAF's sensitive-data flag.
- Traces use an attribute allowlist and remove unrestricted events, event bodies,
  exception messages/stack traces, status descriptions, URL paths/queries and unknown
  resource/scope attributes. Exported vendor tracestate is removed; native causality
  links retain their trace/span IDs and flags with safe attributes.
- Structured logs retain allowlisted fixed event names, safe correlation, node,
  transition, retry attempt, exception type and trace/span IDs. Arbitrary message
  text, formatting arguments, exception bodies and extras are suppressed.
- **No raw complaints, prompts, model content, checkpoint bodies, idempotency keys,
  credentials, connection strings or unrestricted tool arguments/results** belong in
  logs/traces. Business idempotency keys remain in the durable SQL audit only.
- Logging configuration keeps and protects existing platform handlers. Only the
  `maf_double_charge` logger namespace is connected to the API log exporter.
- Uvicorn access handlers retain their destination but use a compatible safe JSON
  formatter. They emit a fixed HTTP event, allowlisted method/status and correlation
  only—not raw request paths, query strings, client addresses or HTTP-version text.
- Live metrics, performance counters and local exporter retry storage are disabled.
  Metric views keep real native GenAI usage/duration and HTTP server duration only,
  with restricted dimensions. No synthetic token metrics are added.

### Tested SDK compatibility seam

The SDK has no public API for deleting ended-span attributes or exception events.
An ordinary `on_end` processor appended to a hosted provider runs **after** its
existing exporter, which is too late. `SafetySpanProcessor` therefore uses OTel
1.44's `_on_ending` hook and a small, isolated span-snapshot mutation seam, before
**all** `on_end` exporters. This preserves the platform's provider and export path.
Keep OTel API/SDK/exporter versions in the tested `>=1.44,<1.45` family and run the
in-memory tests before changing them. MAF's own sensitive-data control is the first
defense; the pre-export filter is defense in depth, not content instrumentation.

Platform logging/export outside the app's namespace and native process metrics are
platform-owned. This app does not claim to replace the platform's global telemetry
policy. Platform role identity is preserved; API role/version come from actual
`OTEL_SERVICE_NAME`/`OTEL_SERVICE_VERSION` settings (package version is the fallback).

telemetry to Azure; deployed ingestion must be verified separately.
